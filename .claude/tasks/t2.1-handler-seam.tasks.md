# Tasks: T2.1 — Handler seam (HandlerRegistry + stub handlers)

Derived from `.claude/specs/t2.1-handler-seam.spec.md` and ADR-0011. Order matters.
Strict scope: interface + value object + registry + 3 stubs + 2 exceptions. No worker
loop (T2.2), no retry/backoff (T2.3), no DLQ (T2.4), no status updates.

## Build steps
- [ ] S1 — `App\Exception\TransientHandlerException` · typed-factory style, mirrors
      `VerificationException`/`QueueException`. Message names provider + event id only.
- [ ] S2 — `App\Exception\PermanentHandlerException` · same style; docblock states it
      means "do not retry — poison/permanently-rejected event → DLQ".
- [ ] S3 — `App\Handler\WebhookEvent` · `final readonly`; promoted props
      `provider`, `eventId`, `eventType`, `payload`, `attempt`; typed accessors.
      Docblock: built by the worker (T2.2) from the MySQL row; carries the RAW payload.
- [ ] S4 — `App\Handler\Handler` interface · `handle(WebhookEvent $event): void`
      (`@throws` both handler exceptions), `provider(): string`. Docblock states the
      transient/permanent/normal-return contract and the idempotency expectation.
- [ ] S5 — `App\Handler\GitHubHandler` · `final`, `provider()` → `'github'`,
      `handle()` no-op with idempotency-contract docblock.
- [ ] S6 — `App\Handler\StripeHandler` · same shape, `'stripe'`.
- [ ] S7 — `App\Handler\PayPalHandler` · same shape, `'paypal'`.
- [ ] S8 — `App\Handler\HandlerRegistry` · lazy `match` `get(string): ?Handler`,
      `null` for unknown. Docblock notes laziness is for symmetry with `VerifierRegistry`,
      NOT operational isolation (stubs take no secrets).
