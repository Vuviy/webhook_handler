## Findings & dispositions

### MAJOR-1 — inner catch-all swallowed post-`handle()` infra faults — **FIXED**
`app/worker.php` — the inner `try` originally wrapped both `handle()` **and** `markProcessed()`. If `handle()` succeeded but `markProcessed()` threw (DB flap), the catch-all `\Throwable` called `markFailed()`, mis-recording a succeeded event as `failed` (audit corruption) and — since the job is already off the queue — never reaching `processed`. It also breaks the handler/infra-fault boundary ADR 0012 Decision 4 protects.
**Applied:** the inner `try` now wraps **only** `$handler->handle($event)`; each catch ends with `continue`; `markProcessed()` is called **after** the try, so a status-write failure falls through to the outer infra backstop (row stays `processing` — the honest stuck-state, with a reaper noted as future work) and a succeeded event can never be recorded `failed`. Re-verified end-to-end after the change.

### MINOR-1 — PSR-12 file-docblock order — **DECLINED (consistency)**
phpcs wants the file docblock before `declare(strict_types=1);`. The reviewer believed `migrate.php` passed clean; it does not — the **same** error fires on `bin/migrate.php` and `public/index.php`. The whole codebase uses `<?php` → `declare` → docblock. Per CLAUDE.md ("read like the surrounding code"), matching the established convention beats satisfying bare `PSR12.Files.FileHeader` for one new file. Declined consciously; a project-wide phpcs ruleset is a separate setup task if ever wanted.

### MINOR-2 — `markProcessing` dropped the ADR's explicit `updated_at=NOW()` — **FIXED (documented)**
The column is `ON UPDATE CURRENT_TIMESTAMP` (migration 0001), so MySQL bumps `updated_at` automatically when `status` changes; an explicit `updated_at = NOW()` would be redundant. Added a docblock note making this reliance explicit rather than adding redundant SQL.

### NIT-1 — `findForProcessing` returns `status`, unread by the worker — **KEPT (conscious)**
The claim guard (`markProcessing`) is the single source of truth for the transition; `status` in the SELECT is cheap and likely needed by T2.3. Kept deliberately.

### NIT-2 — `consume()` comment frames BLPOP `false` as only a version quirk — noted, no change.
### NIT-3 — `decodeJob` `?? null` validation — confirmed sound (rejects missing & wrong-typed fields), no change.
