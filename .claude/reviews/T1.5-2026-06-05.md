## Acceptance criteria

- [x] **AC-1** (valid → 202 + logged `received`; invalid → 401, not enqueued) — ✅
  `IngestionController.php:69-73` maps `Valid` → `record()` (202 + insert `received`)
  and `Invalid` → `rejected(401)` with no persistence/enqueue. Verified end-to-end
  (valid GitHub sig → 202 + 1 row; tampered → 401 + 0 rows).
- [x] **FR-4** (valid → insert `received` + enqueue) — ✅
  `record()` inserts then enqueues only when newly inserted (`IngestionController.php:86-91`).
- [x] **FR-5** (invalid/missing → 401, no enqueue) — ✅ `IngestionController.php:70`.
  Missing signature header is `Invalid` inside the verifier (per `ProviderVerifier.php:38-41`), so it also lands on 401, not 5xx.
- [x] **FR-9** (audit log of authentic events) — ✅ for valid events; rejects deliberately
  not persisted (ADR 0009 §"Do NOT persist Invalid/Error"). Narrow-but-justified reading; see N1.
- [x] **FR-11 / AC-6** (dedupe; re-delivery no double-process, still 2xx) — ✅
  Atomic `INSERT … ON DUPLICATE KEY UPDATE id = id` + `rowCount() === 1`
  (`EventRepository.php:48-61`); duplicate → `false` → no re-enqueue → still 202
  (`IngestionController.php:89,96`). Verified: re-sent delivery → 202, still 1 row, queue +0.
- [x] **NFR-1** (no secret/signature/reason/payload in response) — ✅ bodies are the
  constant `{"status":"accepted"|"rejected"}` (`IngestionResponse.php:27-36`); `reason()`
  is never read in the controller; no raw exception escapes `handle()` (try/catch at
  `:54-60` and `:86-94`).
- [x] **NFR-3** (thin HTTP path, no downstream business work) — ✅ verify → insert →
  RPUSH → return; all heavy work is deferred to the worker (T2.x).

## Findings

| # | Severity | File:line | Issue | Suggested fix |
|---|----------|-----------|-------|---------------|
| 1 | MINOR | `app/src/Http/IngestionController.php:72` | psalm (errorLevel 3) reports **PossiblyNullArgument** at 72:68 and 72:88: `$result->eventId()`/`eventType()` are typed `?string` but `record()` takes `string`. The runtime invariant holds (a `Valid` result guarantees non-empty ids — `VerificationResult.php:40-53`), so this is **analyser noise, not a runtime bug**. But the type contract doesn't express it, so a static gate will fail. | Tighten the contract so the non-null is provable: e.g. add `VerificationResult::isValid()`-guarded accessors, or pass the whole `VerificationResult` into `record()` and read ids there after the `match` already proved `Valid`, or add a typed `@psalm-assert`/dedicated value accessor. (Do not "fix" with a bare cast that hides the invariant.) |
| 2 | NIT | `app/src/Repository/EventRepository.php:54-59` | `execute()` is called with named params but its `bool` return is not checked. With `PDO::ERRMODE_EXCEPTION` (set in `Connection.php`) a failure throws `PDOException` (caught upstream), so this is safe **as long as** the PDO handed in always uses exception mode. | Optional: a one-line note that this relies on ERRMODE_EXCEPTION, or assert it, so a future caller passing a silent PDO can't make a failed insert look like a (false) duplicate. |
| 3 | NIT | `app/src/Http/IngestionController.php:92` | `catch (PDOException | QueueException)` is the right breadth for the *known* throwers (`insertReceived` → PDOException; `enqueue` → QueueException, which already wraps `JsonException` per `Queue.php:96-98`). It is, however, an **allow-list**: if a future `EventRepository`/`Queue` throws a sibling type it would escape `handle()`. Low risk today. | Optional defensive `catch (\Throwable)` → 500 as a final backstop (still no payload in the body), or a comment pinning the contract that these two are the only expected throwers. |
| 4 | NIT | `app/src/Http/IngestionController.php:62-64` | Unknown-provider → 404 is implemented here though ADR 0009 scopes unknown-provider/routing to **T1.6**. The ADR explicitly calls this "forward-compatible / defensive," so it is **not** a scope violation — flagged only for the record. | Keep. No change needed. |

No BLOCKER/MAJOR findings. Specifically checked and found correct:
- **Raw body** is passed straight to `verify()` and stored as `payload` — never re-encoded (`IngestionController.php:67,87`; `EventRepository.php` binds `:payload = $rawPayload`). Byte-exact with what was signed.
- **`hash_equals` / timing-safe compare** is the verifiers' responsibility (T1.2–T1.4), out of T1.5 scope; the controller correctly does not re-implement comparison.
- **Outcome enum handling is exhaustive** — `match` covers `Valid`/`Invalid`/`Error` (`IngestionController.php:69-73`); no `default`, so a future enum case fails loudly (`\UnhandledMatchError`) rather than silently.
- **Misconfig vs forgery separation** — `VerificationException` from `get()` → 500 (`:56-60`), never collapsed into 401. Correct and security-relevant.
- **Header casing** normalised once via `array_change_key_case(..., CASE_LOWER)` before `verify()` (`:67`), honouring the `ProviderVerifier` contract.
- **Dedupe signal** — `rowCount() === 1` is exact for `INSERT … ON DUPLICATE KEY UPDATE id = id` under `EMULATE_PREPARES=false`: 1 = real insert, 0 = no-op duplicate (never 2, because the UPDATE is a no-op). `MYSQL_ATTR_FOUND_ROWS` is **not** set, so there is no false-duplicate/false-new risk. Confirmed by the re-delivery test (queue +0 on the second send).
- **Insert-then-enqueue orphan** — reasoning holds: enqueue throws → 500 → provider redelivers → dedupe re-attempts enqueue. The `received` row is recoverable; a sweeper is correctly deferred to T2.x (ADR 0009, Option F).
- **Scope** — no routing, no 405, no `php://input`/superglobals, no `index.php` wiring leaked in. Controller is pure (VO in → VO out).
- **Conventions** — `declare(strict_types=1)` in all four files; `final` (and `final readonly` on the VO); full type hints; constructor promotion + `readonly`; prepared statement only, no string-concat SQL; typed `App\Exception\*`.

## Verdict
**Approve with nits** — T1.5 meets every in-scope acceptance criterion (AC-1, FR-4, FR-5, FR-9, FR-11/AC-6, NFR-1, NFR-3), the security-critical paths (raw body, misconfig≠forgery, no payload in responses, no escaping exception) are correct, and the design matches ADR 0009. The only thing approaching a real defect is the psalm **PossiblyNullArgument** (#1) — a type-contract tightness issue, not a runtime bug — worth fixing so a static gate stays green. Nits #2–#4 are optional hardening.
