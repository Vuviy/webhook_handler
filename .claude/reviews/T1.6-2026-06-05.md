## Scope reviewed

## Acceptance criteria (the slice T1.6 owns — routing + status codes)
T1.6 is wiring/routing; the data-path ACs (AC-1..AC-6) are exercised end-to-end but mostly owned by T1.1–T1.5. Assessed against ADR 0010's routing contract:

- **GET /** → 200 health JSON — ✅ (`index.php:87-93`).
- **non-GET /** → 405 + `Allow: GET` — ✅ (`index.php:88-90`).
- **POST /webhooks/{provider}** → delegates to `IngestionController` (202/401/502/500/404) — ✅ (`index.php:103-118`).
- **non-POST /webhooks/{provider}** → 405 + `Allow: POST` — ✅ (`index.php:104-106`).
- **/webhooks or /webhooks/** (no provider) → 400 — ✅ (`index.php:97-99`).
- **anything else** → 404 — ✅ (`index.php:121`).
- **NFR-1** (no Throwable/secret/payload leaks into a response body; 500 body is a constant) — ✅ for the response body; one log-side caveat below (finding #1). The 500 body is the literal `{"status":"error"}` and `$e` goes to `error_log` only (`index.php:54-59`).
- **DB/Redis opened only on the matched webhook POST** — ✅. `new IngestionController(...)` (which calls `Connection::fromConfig` + `Queue::fromConfig`, both of which open sockets) sits inside the POST branch only (`index.php:108-112`); health/400/404/405 open nothing.

## Notable things done correctly (worth keeping)
- **Raw body read once, falsy-safe.** `file_get_contents('php://input')` with an explicit `=== false` guard (`index.php:43-46`) correctly preserves a literal `"0"` body that a `?: ''` would have dropped — directly serves the raw-bytes signature rule.
- **Backstop placement.** `dispatch()` is a function specifically so controller construction (DB/Redis dial-up) executes *inside* the `try` (`index.php:54-59, 70-81`). A MySQL/Redis outage therefore yields a clean constant 500, never a leaked trace — this is exactly the NFR-1 fix the T1.5 review asked for.
- **400 vs 404 split is correct and matches the ADR.** `/webhooks` and `/webhooks/` (structurally malformed, no provider) → 400 in the router (`index.php:97-99`); a well-formed but unknown provider (`/webhooks/bitbucket`) is left to the controller's 404 (`IngestionController.php:63-64`). The two failures do not collapse.
- **Header reconstruction is sound.** `HTTP_*` only, prefix stripped, `_`→`-`, lower-cased (`ServerRequest.php:94-101`). Deliberately excluding `CONTENT_TYPE`/`CONTENT_LENGTH` (the non-`HTTP_` pair) is documented and safe: every provider signature header (`X-Hub-Signature-256`, `Stripe-Signature`, `Paypal-*`) arrives as `HTTP_*`, and the controller re-lower-cases keys anyway (`IngestionController.php:68`), so the double-fold is harmless.
- **Path-parsing edge cases hold up** (verified with `parse_url` in the container): trailing slash tolerated via `rtrim` (`index.php:103`); query string stripped (`ServerRequest.php:46`); `/webhooks//github` and `/webhooks/github/extra` correctly fall through to 404; `%2F` is not decoded, so an encoded slash stays one opaque segment and the controller rejects the unknown provider with 404.
- **Method default.** `REQUEST_METHOD ?? 'GET'` (`ServerRequest.php:43`) prevents a missing-method type error downstream; combined with the route table a missing method on `/` still yields a defined 200/405, never a 5xx.
