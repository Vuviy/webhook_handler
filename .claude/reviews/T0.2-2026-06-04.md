## Security review (most important axis)
- **No secret leakage in exceptions/logs.** `ConfigException::missing/notInteger` interpolate only
  the KEY (`ConfigException.php:19,24`); the value is never touched. ✅
- **Secrets encapsulated, not dumpable.** `ProviderSecrets` and `DatabaseConfig` expose typed getters
  only; no `__toString`, no array export, no `var_dump`-friendly public state (all promoted props are
  `private`). `password()` is explicitly annotated `/** Secret — do not log. */` (`DatabaseConfig.php:48`). ✅
- **Secrets only from env.** No hardcoded secret anywhere; `app/.env` ships with empty secret values and
  is git-ignored (`git check-ignore app/.env` → match). ✅
- This subtask performs no signature/crypto work, so `hash_equals`, raw-body and replay rules are N/A here.

## Design / correctness notes
- **Precedence reasoning is correct.** phpdotenv `createImmutable()->safeLoad()` (confirmed **v5.6.3** in
  the container; the host `vendor/` is a stale v3 copy — review used the container version) does not
  overwrite vars already present in the process env, and populates `$_ENV/$_SERVER` only for gaps.
  Reading `$_ENV[$key] ?? $_SERVER[$key]` (`Env.php:22`) therefore yields compose-injected values first
  and `app/.env` as fallback, exactly as ADR-0003 Decision-1 Option A intends. `safeLoad()` tolerates a
  missing file. ✅
- **`ProviderSecrets` optional is spec-consistent.** ADR-0003 Consequences and the health requirement say
  the app must boot before any provider is configured; nullable getters defer the failure to each
  verifier (T1.x). ✅
- **Fail-fast for DB/Redis** via `Env::required`/`requiredInt` matches the required-vs-optional contract. ✅
- **No over-engineering.** Three small readonly VOs + a thin `Env` reader + one exception is proportional
  and matches "avoid abstractions with one implementation" — none of these are interfaces/strategies. ✅
