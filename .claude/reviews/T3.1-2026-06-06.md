## Detailed assessment of the called-out areas

1. **NFR-1 payload/secret safety** — ✅ Strongest possible: the SELECT list is pinned to safe
   metadata columns, so `payload` (the raw signed bytes / LONGTEXT) cannot leak even by accident —
   safer than `SELECT *`. Proven at runtime with a marker payload that did not surface. `counts`
   uses `COUNT(*)` only. `dlq_size` is a length. The controller invents no local error rendering;
   any throw rides the front-controller Throwable backstop → `{"status":"error"}` 500 with no
   detail. No leak path added.

2. **PARAM_INT LIMIT under non-emulated prepares** — ✅ Correct. `bindValue('limit', $limit,
   PDO::PARAM_INT)` is the right fix for the `ATTR_EMULATE_PREPARES => false` gotcha the ADR
   flagged; a string-bound LIMIT would 500. Verified executing live. The argument is a fixed
   constant (no user input), so there is no injection surface; the integer bind is correct
   regardless.

3. **Counts normalisation** — ✅ All four enum keys pre-seeded to 0 and overwritten only for
   statuses with rows; `array_key_exists` guards a future/unknown status from polluting the stable
   contract. Live `GET /` on an empty table returned all four keys at 0; seeded data returned
   `failed:2`. The grouped query is served by `idx_status` (migration 0001 confirmed).

4. **No-DB/Redis-on-/health invariant** — ✅ Preserved. `/health` constructs no controller and
   opens no connection; the dashboard builds `EventRepository`/`Queue` strictly inside the matched
   `GET /` branch — mirroring how the webhook-POST branch scopes its connections. An infra outage
   cannot break the liveness probe.

5. **Single ownership** — ✅ Upheld. The new SQL lives in `EventRepository`; `webhooks:dlq` stays
   sealed as `Queue::DLQ` with `deadLetterSize()` an exact read-only mirror of `size()`. No SQL or
   Redis key leaked into `DashboardController` or `index.php`.

6. **Scope discipline (T3.1 reads only)** — ✅ Clean. `deadLetterSize` is `lLen` only — it does NOT
   pop, drain, or re-queue the DLQ (that is T3.2). No write path was added on the dashboard route.
   The Queue/ADR docblocks correctly re-state the drain as T3.2 debt.

7. **Conventions** — ✅ `declare(strict_types=1)` in all files; `DashboardController` is `final`
   with constructor-promoted `readonly` collaborators; full type hints and precise `@return`
   shapes on both new repository methods; `JSON_THROW_ON_ERROR` on encode (a half-formed body
   becomes a throw → 500, never a truncated 200). No abstraction added for its own sake — the
   controller is a thin, pure orchestrator, matching `IngestionController`.

## Verdict
**Approve with nits.** T3.1 satisfies FR-10 / AC-5 with the smallest delta ADR 0016 prescribed:
JSON-only, no render-contract change, dashboard at `/` with the liveness probe moved to a
dependency-free `/health`, and three index-served, single-ownership read accessors. NFR-1 is
upheld with a column-pinned SELECT proven at runtime to exclude `payload`; the PARAM_INT LIMIT
gotcha is handled correctly; the no-DB-on-health invariant and the T3.2 read-only scope fence are
both respected. Only one MINOR (ambiguous timestamp formatting, deferrable to the static-front
follow-up) and three NITs (one phpcs docblock line, the documented non-atomic snapshot, the
documented health-route move). No BLOCKER, MAJOR, or security concerns.
