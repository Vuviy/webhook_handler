## Detailed safety analysis

**(1) Flag-only handler — correct and safe.** `$onSignal` does only `$shouldStop = true;`. No `exit`, `throw`, or I/O. Canonical async-signal discipline: the handler may run at an arbitrary VM tick, so it must do nothing that could leave shared state half-mutated. A bool assignment is safe at any tick.

**(2) `while (!$shouldStop)` guarantees finish + no new claim — verified for every landing point.** The condition is evaluated only at the top of each iteration, so a signal landing anywhere in the body lets that body complete, then the loop re-tests and exits before `promoteDue()`/`consume()` claim anything new:
- During `promoteDue()` — sweep finishes (at-least-once safe); top breaks.
- During BLPOP (idle) — phpredis runs BLPOP to its timeout (does NOT abort on the signal, confirmed by diagnostic) → returns null → `continue` → condition re-tested → exit. Worst-case latency ≤ `BLPOP_TIMEOUT_SECONDS` (5s), inside the 10s grace. No job claimed.
- After BLPOP returns a job, before `markProcessing` — this one job is claimed and handled, then top breaks. Honours "finish the in-flight job."
- Mid-handler (between `markProcessing` and `markProcessed`) — handler runs to completion, `markProcessed` writes, top breaks. Row reaches a clean terminal state — the exact case graceful shutdown protects.
- In a retry/DLQ branch — `retryOrFail`/`deadLetter` complete (each `continue`s), top breaks.
- In `sleep(INFRA_BACKOFF_SECONDS)` — async signal interrupts `sleep`, loop continues, top breaks.

The idle-tick `continue` correctly re-evaluates the loop condition, so the explicit idle-tick `break` mentioned in ADR D2/Option C was ultimately not needed — the as-built `while (!$shouldStop)` is functionally equivalent (the ADR's D2 "as built" note already records this). Benign divergence, not a defect.

**(3) `if ($shouldStop) break;` in the outer catch — correct.** With async signals the handler runs the instant the signal arrives, so any interrupted-syscall throw reaching the catch arrives with `$shouldStop` already `true`. Discriminating on the flag (not brittle phpredis error-string matching) is right. The only theoretical loss: a genuine infra exception that coincidentally throws in the same iteration after a stop is swallowed instead of logged — immaterial during an intentional teardown (at-least-once + the guarded claim cover any half-done work; re-delivered on next start).

**(4) SIGQUIT handling — semantically acceptable and coherent.** SIGQUIT's default action is terminate+core-dump; for a long-running CLI worker, converting it to graceful shutdown is reasonable, and specifically warranted because the base image's inherited `STOPSIGNAL` is SIGQUIT. `stop_signal: SIGTERM` (primary path) + the SIGQUIT handler (raw `docker stop` path) is genuine belt-and-suspenders. Losing SIGQUIT's debug core-dump is negligible here.

**(5) `pcntl` in the shared Dockerfile — acceptable.** Core extension via `docker-php-ext-install` (no PECL, no system libs). The FPM `php` service gains a harmless unused extension; a separate worker image would be over-engineering for one extension. Documented in ADR D0.

**(6) No scope bleed.** No DLQ-drain (T3.2) and no stuck-`processing` reaper logic; the docblock re-states both as remaining debt without implementing them.

**(7) Conventions.** `declare(strict_types=1)` present; the closure is fully typed (`int $signal): void`) and `static`; comments accurate; no secrets/payloads logged.
