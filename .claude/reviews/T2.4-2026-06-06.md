## Detailed assessment of the items called out for scrutiny

1. **FR-8/AC-4 on BOTH paths** — ✅ Satisfied. The two seams ADR 0013 D5 reserved are both
   rerouted *by addition*: one call swapped in `retryOrFail` (`markFailed` → `deadLetter`), one
   in the worker's permanent `catch`. They funnel through the single `RetryScheduler::deadLetter`,
   so they cannot drift — the same consolidation win `retryOrFail` bought for the transient pair.

2. **markFailed-before-RPUSH ordering** — ✅ Sound and well-justified. DB-first means the
   tolerable partial state (crash in the gap) is a `failed` row without a DLQ entry: visible on
   the dashboard via `status`, terminal, and reconcilable from `status='failed'` by the T3.2
   drain. The rejected order (RPUSH-first) would risk a stuck-`processing` orphan that the guarded
   `markProcessing (AND status='received')` can never re-claim — strictly worse. This is the same
   ordering rule as `retryOrFail`'s retry path, so the failure path has ONE rule throughout. The
   non-transactional gap is explicitly documented at `RetryScheduler::deadLetter` and in ADR 0014
   Consequences. Acceptable and documented. ✅

3. **No T2.5 / T3.2 bleed** — ✅ Clean. `deadLetter` is a write-only RPUSH; nothing drains or
   re-queues the DLQ (that is T3.2), and no SIGTERM handling was added (T2.5). The worker docblock
   correctly lists both as REMAINING DEBT and the idle-tick as SIGTERM's future home. Scope fence
   from the SOP respected.

4. **`deadLetterFailed` payload/secret leak (NFR-1)** — ✅ None. The factory message is
   `Failed to dead-letter the job for event "%s".` with only the event id — identical discipline to
   `enqueueFailed`/`scheduleRetryFailed`. No payload, no secret, no raw bytes. Mirrors the class
   docblock's stated invariant.

5. **Conventions** — ✅ `declare(strict_types=1)` present in all changed files; `final` on `Queue`,
   `RetryScheduler`, `QueueException`; full type hints on the new `deadLetter` signatures
   (`: void`, typed params); `?Throwable $previous = null` matches the sibling factories.
   `hash_equals` is N/A here (no signature comparison in this path). Throw-don't-silently-drop is
   consistent: `deadLetter` throws on a `false` RPUSH exactly like `enqueue`/`scheduleRetry`,
   upholding the queue layer's one invariant for the one list whose purpose is to not lose jobs.

6. **DLQ envelope `attempt = job->attempt()`** — ✅ Correct. Exhaustion is reached only when
   `job->attempt() + 1 > MAX_ATTEMPTS`, i.e. `job->attempt() == 3`, so the envelope records `3`
   (the last attempt that ran) — matching AC-4's "after 3 failures". For a permanent failure it is
   the throwing attempt (often 1). Truthful and coherent with the DB `attempts` column written by
   `markForRetry` on the retried path. No spurious increment.

## Verdict
**Approve with nits.** T2.4 meets FR-8 and AC-4 on both the exhaustion and permanent paths,
keeps the DB-first ordering with a documented, strictly-better partial-failure state, leaks no
secret or payload (NFR-1), throws-not-drops on a failed RPUSH (NFR-4), carries the correct
`attempt`, and respects the T2.5/T3.2 scope fence — all by addition, not rewrite, as ADR 0013 D5
pre-committed. The only item worth a conscious decision before moving on is finding #1: the
`$handler === null` guard in the worker is a remaining direct-`markFailed` terminal site that does
not reach the DLQ; route it through `deadLetter` or document the exemption. Findings #2/#3 are
informational.
