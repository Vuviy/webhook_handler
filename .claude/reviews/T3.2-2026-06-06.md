- **Reviewer:** code-reviewer
- **Diff:** `git diff master...HEAD` (uncommitted working tree: `Queue.php`, `EventRepository.php` modified; `DlqRequeue.php`, `DlqRequeueReport.php`, `bin/requeue-dlq.php` new)

## Scope

T3.2 adds the recovery half of the dead-letter story: an operator CLI that drains
`webhooks:dlq` back onto `webhooks:queue`. Reviewed against ADR 0017 (D1 CLI,
D2 drain-all, D3 cross-store ordering, D4 ownership split), the spec, and the
`php-conventions` / `queue-processing` skills.

## Acceptance criteria

The feature-level ACs (AC-1..AC-6) are not in T3.2's scope; T3.2 delivers FR-8's
recovery half and resolves spec open question #4. I assess it against the ADR's
own decisions:

- D1 (CLI not button) — ✅ `bin/requeue-dlq.php` mirrors `bin/migrate.php`, lives above `public/`, zero new HTTP/CSRF/auth surface.
- D2 (drain-all, bounded by snapshot) — ✅ `drainAll()` reads `deadLetterSize()` once and loops at most that many times; no by-id mode shipped (correctly deferred).
- D3 (pop → DB-reset → push, resumable per-entry LPOP) — ✅ ordering is exactly as specified; reset-before-push enforced; LPOP-per-entry, no LRANGE/DEL.
- D4 (Queue mechanism + EventRepository reset + DlqRequeue orchestrator + thin CLI) — ✅ ownership split is clean: Redis key+envelope sealed in `Queue`, SQL in `EventRepository`, ordering+tally in `DlqRequeue`, reuse of `enqueue($id,$provider,1)` for the push, reuse of `decodeJob()` for the decode.

The implementation is faithful to the ADR. Findings below are mostly robustness
and convention nits; one MAJOR on uncaught Redis faults.

## Detailed assessment

**Security (NFR-1).** ✅ No secrets touched or logged. The CLI writes only
`provider` + `event_id` + a typed `$e->getMessage()` to STDOUT/STDERR; the raw
`payload` never enters the Redis envelope or this path. `requeueFromDlq` clears
`last_error` (intended, ADR D4 resolved). No new HTTP surface, no auth/CSRF
question — the `docker exec` boundary is the authorization, as the ADR argues.
`hash_equals`/signature concerns are not in this path.

**Cross-store crash-safety (D3).** ✅ Correct and load-bearing. Order is
LPOP (`requeueOneFromDeadLetter`) → DB reset (`requeueFromDlq`, before push) →
`enqueue(...,1)` push, exactly per ADR Option G. The only possible crash residue
is the recoverable "envelope popped, row still `failed`" (visible on the
dashboard) or "row `received`, envelope not yet pushed" (re-pushable on re-run).
The dangerous "live envelope over a `failed` row that the worker silently skips"
(`worker.php:136-137`) is made impossible because the push is last. The loop is
bounded by the start-of-run `deadLetterSize()` snapshot, so a worker
re-dead-lettering during the drain cannot live-lock it; the `$job === null` early
break defends against an under-count. Good.

**Idempotency / at-least-once (NFR-2).** ✅ Two composed guards: `requeueFromDlq`'s
`AND status = 'failed'` (`EventRepository.php:218`) and the worker's
`markProcessing` `AND status = 'received'`. A re-run, or an envelope whose row was
meanwhile re-driven, is a harmless no-op counted as `skipped`. `attempts = 0` +
fresh `attempt = 1` envelope correctly resets the budget — the naive-re-push
bug the ADR's Context section calls out is genuinely avoided.

**Single ownership (D4).** ✅ `webhooks:dlq` / `webhooks:queue` key names and the
envelope schema stay sealed in `Queue` (LPOP+`decodeJob`, re-push via existing
`enqueue`). All SQL stays in `EventRepository`. `DlqRequeue` holds ordering+tally
only, and is correctly a separate `final` class (recovery direction) rather than
bolted onto `RetryScheduler` (failure direction). `DlqRequeueReport` is a clean
`final readonly` value object. The orchestrator is I/O-free; only the CLI writes
to the console (via the `$onEntry` closure) — a nice separation.

**Conventions.** ✅ `declare(strict_types=1)` on all files; full type hints;
`final` / `final readonly`; constructor promotion + `readonly`; prepared
statements only. Class/method docblocks are thorough and tie back to the ADRs.

**Reliability detail.** ✅ Every `Queue` write still throws loudly on a `false`
Redis return (`enqueue` keeps the no-silent-drop invariant). The corrupt-entry
path continues the drain rather than aborting on one poison envelope, per the
ADR's resolved edge cases. The `total() === 0` "DLQ is empty" message matches the
`migrate.php` "up to date" analogue.

## Verdict

**Request changes** — the implementation is faithful to ADR 0017 and the
crash-safety / ownership / idempotency reasoning is correct and well-executed.
The single reason for "request changes" rather than "approve with nits" is
finding #1 (MAJOR): a mid-drain Redis fault escapes the CLI's typed-error
backstop because `RedisException` is not in the catch list, breaking the
`exit(1)` + typed-message discipline the ADR explicitly promises for the
"Redis down" infra fault. That is a one-line fix (add `RedisException` to the
catch, or catch `\Throwable` like `worker.php`). With #1 addressed (and the MINOR
line-wrap #3), this is a clean approve.
