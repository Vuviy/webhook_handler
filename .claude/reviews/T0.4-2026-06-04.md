## Specific questions raised by the implementer

**(a) phpredis Warning emitted before the typed exception.**
Reproduced. `Redis::connect()` raises a native PHP `Warning`
(`php_network_getaddresses: getaddrinfo for nope_no_host failed ...`) from
`Queue.php:47` *before* the catch turns it into a `QueueException`. The warning text
contains only the host (`nope_no_host`) — **no secret leaks** — so this is a noise/log-
hygiene issue, not a security one. In PHP-FPM this Warning lands in the FPM error log
in addition to the clean typed exception, producing duplicate, lower-quality noise for
the same event. Worth suppressing narrowly. See finding #1.

**(b) Deferring `deadLetterSize()` against the ADR.**
The ADR explicitly proposed including `deadLetterSize()` (lines 113-116) and declaring
the `RETRY`/`DLQ` key constants now (lines 120, 122-124). The implementer deferred both
to T2.x. Judgement: **the deferral is reasonable and arguably cleaner**, but it is a
*conscious deviation from an approved ADR* and should be recorded. Declaring a `DLQ`
const with no method, or a `deadLetterSize()` reading a list the worker has not yet
defined, is forward-reference debt with zero exercised behaviour; deferring keeps T0.4
honestly minimal. However, the ADR currently still says "include `deadLetterSize()`",
so the document and the code now disagree. See finding #2 (MINOR) — update the ADR
(status/decision note) so the record matches reality.

**(c) Error handling in `fromConfig` — `connect()` false vs `RedisException`.**
Both paths are handled and both are correct:
- `catch (RedisException $e)` → `connectionFailed($host,$port,$e)` (`Queue.php:48-50`).
- `if ($connected === false)` → `connectionFailed($host,$port)` (`Queue.php:52-54`).
Confirmed against ext-redis 6.3.0: `Redis::connect()` has return type `bool`, so the
`=== false` strict check is exactly right (no truthiness trap). No gap found here.

**(d) Type safety of `lLen`/`rPush` return values.**
Confirmed via reflection on ext-redis 6.3.0: both `lLen` and `rPush` declare
`Redis|int|false`. `size()` casts `lLen` with `(int)` (`Queue.php:72`), which collapses
`false`→0 and the `Redis` (pipeline) case is unreachable here since the client is not in
MULTI/PIPELINE mode — acceptable. `enqueue()` ignores the `rPush` return entirely
(`Queue.php:66`); if RPUSH returned `false` the caller would believe the job was queued
when it was not. phpstan level max reports **no errors** on both files (it uses the
native runtime signatures, so this is a real clean pass, not a stub gap). The ignored
`rPush` result is therefore a *robustness*, not a *type-checker*, issue. See finding #3.

## Notable strengths
- Class docblock (`Queue.php:13-28`) directly addresses the single-implementation rule and
  correctly argues why `Queue` escapes it (owns key name + envelope), exactly as ADR-0005
  decided. The wrapper has **not** silently grown into a passthrough — confirmed.
- `QueueException` mirrors `DatabaseException` faithfully; messages are secret-safe by
  construction (only `host:port` and `event id`).
- Envelope encoding uses `JSON_THROW_ON_ERROR` with a typed wrap (`encodeFailed`) — correct,
  and the message names the event id only.
- Injected `\Redis` constructor + static `fromConfig` keeps the class unit-testable without a
  live server, matching the T0.3 ergonomics.

## Verdict
**Approve with nits.** All T0.4 acceptance criteria are met, security/secret-safety is sound,
phpcs (PSR12) and phpstan (max) are clean, and every implementer claim was independently
reproduced. The deviations from ADR-0005 (deferred `deadLetterSize()` / key consts) are
reasonable but should be reflected back into the ADR (finding #2). The phpredis double-report
Warning (finding #1) and the ignored `rPush` result (finding #3) are worth tidying but block
nothing. No BLOCKER or MAJOR findings.
